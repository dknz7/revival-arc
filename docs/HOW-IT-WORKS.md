# How Vivarc works

Vivaldi's UI is a web page (`window.html`). Vivarc adds one script and one stylesheet to it.

| Piece | Where it lives | What it does |
|---|---|---|
| CSS | Embedded in `vivarc.js` and added to the UI as a `<style>` element (source: `src/css/vivarc.css`) | Styles. Every rule is scoped to `#browser.vm-on`, a class the JS adds. No CSS-mods folder or browser flag is needed, and it never conflicts with your own CSS mods. |
| JS | `<Vivaldi.app>/.../vivaldi/vivarc.js`, referenced from `window.html` by one marked block | The sidebar, command bar, toast and theme editor. Rebuilt from `src/js/` by `vivarc.py apply`. |
| Data | A bookmarks folder with `Favorites` and `Pinned` subfolders (created on first run, from a normal window; a space's own folder with its `Pinned` the first time it is shown there, never from a private window) | Your favorites and pinned folders. Plain bookmarks: they sync, export and back up like any others. |
| Settings | `~/.vivarc/config.json` | See below. |
| State | `~/.vivarc/state.json`, `~/.vivarc/backup/` | What the installer changed and the original values, used by `uninstall`. |

## Why a Vivaldi update removes the JS

An update replaces `Vivaldi.app`, including `window.html`. Run `./vivarc.py update` after updating: it pulls (git checkout) or downloads the latest release when there is one, then re-runs `install`. The installer leaves `~/Applications/Update Vivarc.app`, which opens `~/.vivarc/Update Vivarc.command` in Terminal; that script runs `update` (it quits Vivaldi) and reopens Vivaldi. `~/Applications/Uninstall Vivarc.app` does the same for `~/.vivarc/Uninstall Vivarc.command`, which runs `uninstall`. They are generated locally (the app by `osacompile`, ad-hoc signed), so macOS does not quarantine them, the app can sit in the Dock, and `uninstall` removes them all. The optional reminder (`vivarc.py reminder on`) is a LaunchAgent, `~/Library/LaunchAgents/com.vivarc.reminder.plist`, that runs `vivarc.py remind` at login, every hour and when Vivaldi's `Info.plist` changes. `remind` only reads: if `window.html` has lost the Vivarc block (or `vivarc.js` is missing) it shows one dialog, at most every 12 hours, and on yes opens the update script in Terminal. When Vivarc is in place it also asks GitHub for the latest release tag (a redirect, nothing is downloaded) and, if that is newer than the installed version, shows one dialog per release (remembered in `~/.vivarc/offered`) with the same yes path. A git clone (Revival Arc's fork) is never offered a release: it updates with `git pull` from its own origin, so upstream's release number is not an update for it. It still gets the "Vivaldi was updated" dialog. A background job cannot do the update itself: macOS only lets a terminal you have granted App Management edit `Vivaldi.app`.
`./vivarc.py status` tells you whether the JS is in place. Until you re-apply, Vivaldi simply looks like normal Vivaldi.

## Configuration

`~/.vivarc/config.json`, then run `./vivarc.py apply`:

```json
{
  "hideWorkspaceButton": true,
  "autoConfigureProfiles": true,
  "compactBottomBar": true,
  "suggestions": "ddg",
  "spaceFolderTitle": "Vivarc"
}
```

- `hideWorkspaceButton`: hide Vivaldi's Workspaces button at the top of the sidebar (on by default).
- `autoConfigureProfiles`: let Vivarc set up profiles created after install (see below).
- `compactBottomBar`: shrink the bottom toolbar (profile button) to Arc's proportions.
- `suggestions`: `"ddg"` sends what you type in the command bar to DuckDuckGo's autocomplete endpoint; `"off"` sends nothing.
- `spaceFolderTitle`: name of the folder created on first run.
- `peek`: `false` keeps the community Peek mod out until you uninstall (uninstall deletes this file). From the next `install` or `apply` on, `install` skips the download and `apply` leaves it out of the bundle even if `~/.vivarc/peek/` is still there. `--no-peek` does the same for one run only, and "Update Vivarc" passes no flags. When Peek is in, it opens on shift+click on a link or a middle-button hold, never on a plain click. `17-peek.js` fits Peek to Vivaldi 8.3 at runtime without touching its pinned file: it catches Peek's instance as `window.ArcPeekDebug` is assigned, wraps `_moveParallelTabToMainWindow` so a preview made into a tab is first put into the space on screen beside its source with `native.setSpace` (8.3 drops the space Peek writes), closes the runtime tab Peek leaves open after Open in New Tab, and keeps Peek's tabs out of the sidebar, Open Tabs, the command bar and Clean Up while a preview is open, in every window (`workspaces.isPeekTab`; each window's live preview tab ids are on the background page, `__vivarcPeekLive`, and a preview made into a tab leaves at once), and Recently Closed entries that carry Peek's identity in the closed tab's own `vivExtData` (Vivaldi keeps it in session entries) out of the dropdown (`workspaces.peekSession`): Peek's runtime tab (`arcPeekRuntime`), or a preloaded tab this file marked while it was a live preview (`vivarcPeekPreview`, cleared before a promotion, with up to 3 checked tries; a mark that can't be cleared turns marks off as identity for good, `peekMarkStuck` in Vivarc's store, so the user's tab is never hidden). An address, time or count never hides an entry. A runtime tab Peek adopted into the tab strip (`arcPeekAdopted`) is the user's. Shift+click anywhere else (range selection, extending a text selection) is left to the page. The bundle rewrites Peek's own defaults (alt+click, plus a plain click in pinned tabs and on Google) and leaves Peek out if the downloaded file's text has changed (`PEEK_TRIGGERS` in `vivarc.py`). Peek also reads overrides from a shared config other Awesome-Vivaldi mods can write (`mods.arcPeek` in their `.askonpage/config.json`). Nothing in Vivarc writes it, but another mod that sets `autoOpenList` there brings plain-click Peek back.

`compactBottomBar` and `suggestions` are only the starting values: **Vivarc Settings** (Cmd+T, `settings`) overrides them per profile, live. `01-settings.js` holds the schema (one entry per switch, with the marker class it toggles on `#browser`) and the precedence (saved, then config, then default); `45-settings.js` is the overlay. The `glass` switch only adds the class `vm-glass`, and the `glassOpacity` slider (a `range` entry in the schema, 15 to 95, clamped when read) sets `--vm-glass-opacity` on `#browser`, which every glass fill mixes with; the rules at the end of `vivarc.css` do the rest (the regular variant of Apple's material: blurred, saturated backdrop, translucent fill, specular rim; floating surfaces and the sidebar only, never rows inside them). Vivarc's surfaces sit in Vivaldi's UI layer, where `backdrop-filter` also blurs the page behind floating ones; the sidebar blurs the window background, so it shows real glass over a theme with a background image. `prefers-reduced-transparency` and `prefers-contrast` are supported by Vivaldi's Chromium and switch the surfaces back to solid. Windows of a profile stay in step through a `BroadcastChannel`. Only switches that apply live belong there: anything that writes Vivaldi's Preferences (shortcuts, toolbars) is read at launch, so it stays out.

## What the installer changes

Per Vivaldi profile (`Preferences`): the tab bar goes left; `Cmd+T` is freed from "New Tab" and "Quick Commands" (the command bar listens for it itself);
`Cmd+Shift+C` copies the page URL; `Cmd+S` no longer saves the page: it hides and shows the sidebar of the window it is pressed in, which is Vivarc's own per-window hide (`12-sidebar-hide.js`), not a Vivaldi command (the installer takes `Cmd+S` off every Vivaldi command that holds it, and binds it to none, on every install and update; for a profile set up another way, Vivarc does the same on the profile's first start, once: `05-bootstrap.js` `freeKey`, flag `sidebarKeyFreed`, logging `[vivarc] Ctrl+S freed from <COMMAND>`; Vivaldi reads its key table at startup, so the change is complete from the next start); `Ctrl+Tab` and `Ctrl+Shift+Tab` (Ctrl on a Mac too) are the tab switcher's: Vivarc takes them from Vivaldi's tab cycling (`COMMAND_TAB_SWITCH_FORWARD_SETTING` and `_BACK_SETTING` in Vivaldi 8.3's defaults) the same way, on the profile's first start, once (flag `tabKeysFreed`, logging `[vivarc] Ctrl+Tab freed from <COMMAND>`; the installer itself does not touch them); the `Spacer` and Workspaces items are removed from the tab bar toolbar and the VPN button becomes the Downloads button; the address bar and back/forward/reload move into the sidebar toolbar (the top bar is hidden); the panel icon bar moves to the right and auto-hides (Vivaldi's auto-hide switch is on; the sidebar starts visible, and hiding it is Vivarc's own, not part of the auto-hide switches); the bottom status bar only overlays on hover; the sidebar width starts at 323 unless you set one.
Existing shortcuts are kept. Nothing else in Vivaldi's settings, flags or `Local State` is touched. `uninstall` restores the original values.

## Profiles created later

`install` configures the profiles that exist. For a profile created afterwards, the JS (through `vivaldi.prefs`) applies the same
settings the first time it opens; they take effect immediately, no restart. It also opens the guide page in place of Vivaldi's welcome tab.
`uninstall` finds profiles that carry Vivarc's settings but have no snapshot and resets those keys to Vivaldi's defaults.
Set `"autoConfigureProfiles": false` to skip this and configure profiles only with `install`.

## Files in `~/.vivarc/`

`start/` (guide page), `peek/` (downloaded Peek), `icons.js` (Arc site icons), `import/`, `backup/`, `config.json`, `state.json`.
`apply` refreshes `start/` and rebuilds the bundle (stylesheet included).

## Limits

- Vivaldi profiles are the equivalent of Arc spaces; each is its own window (switch with Cmd+`).
- Vivaldi's own UI code cannot be called from a mod, so Cmd+T opens Vivarc's command bar, not Vivaldi's Quick Commands (Cmd+E and F2 still do).
- macOS and Windows (see the README for the install lines).

## Notes for contributors

Things that cost time to find out:

- Vivaldi toolbar buttons are found with `[data-name="<PanelId>"]` (for example `PanelDownloads`), not a `name` attribute.
- They ignore a bare `.click()`. Send `pointerdown`, `mousedown`, `pointerup`, `mouseup`, `click` in that order.
- Changing the layout inside a `dragstart` handler makes Chromium cancel the drag. Defer it with `requestAnimationFrame`.
- Re-rendering the sidebar while a drag is running detaches the dragged node. Renders are held back until `dragend`.
- A tab row's `dragstart` also writes `application/x-vivarc-tab` (`{kind, tabId, windowId, pass}`); HTML5 drag data crosses windows (measured). Another window's sidebar sees the type in `dragover` (types only; the data is readable in `drop`), accepts with `dropEffect = "move"`, and `dropAcross` in `10-sidebar.js` moves the tab in (`workspaces.crossDrop` and `acrossIndex` decide; the write is `tornData(tab, shownSpace)`). Anything can put that type on a drag (a web page, another app), so `pass` is a fresh `crypto.randomUUID()` that `dragstart` also leaves on the shared background page (`__vivarcDragPass`, the string `"<tabId>:<pass>"`, so the background page holds nothing of the window); `crossDrop` takes the drop only when both match, the taking window removes it, and the dragging window withdraws it 2 s after its `dragend` (the other window's `drop` and this `dragend` are separate events). A private window has its own background page, so a drag between a normal and a private window would be refused (not measured).
- The wallpaper behind the sidebar (setting `sidebarWallpaper`, class `vm-wallpaper`, CSS only; upstream issue #62). Measured on 8.3: with a theme that has a background image (and its UI transparency), Vivaldi sets `--browserBackgroundImage`, `--browserBackgroundSize`, `--browserBackgroundPosition` (and `--browserBackgroundRepeat` for a tiled one) on `#browser` and paints a heavily blurred copy (`--browserBlurredImage`) behind the whole window, which the sidebar (`#tabs-tabbar-container`, transparent there) already shows. The option paints the image itself on the sidebar with Vivaldi's own size, position and repeat, `background-attachment: fixed` so it lines up with the window, under a scrim of the theme's `--colorBg` (58%; with Liquid Glass the glass opacity, at least 45%, with the glass sheen on top). `vm-themed` (a Vivarc space colour) wins, and `prefers-reduced-transparency` / `prefers-contrast: more` drop the image. Vivaldi loads a theme's image when the theme is applied at start (a theme switched with `vivaldi.prefs.set` while running did not get its image in the sandbox).
- Back closes opened tabs (`17-back-closes.js`, setting `backCloses`, off by default; from upstream's open PR #168 without its swipe detection): `webNavigation.onCreatedNavigationTarget` records which tab a link opened a tab from (in memory, so not across a restart). Back closes such a tab, after activating its opener, only when `back.shouldClose` agrees: it is the tab on screen, it cannot go back (the webview's `canGoBack()`, read synchronously at the press, before Vivaldi's own Back can commit), its opener is open in the same window and both are in the space the record shows (activating an opener parked in another space would be G1), and it is not Vivaldi-pinned, a pin's or favorite's tab or in a split view. Vivaldi does nothing on Back with no history, so each Back is caught on its own (measured on 8.3): the keys come as `onKeyboardShortcut` and are matched against `COMMAND_PAGE_BACK`'s chords in `vivaldi.actions` (skipped while the UI's cursor is in a field; a Cmd+Left on a Mac also asks the page, by `executeScript`, whether its cursor is in a text field); the toolbar's Back is `disabled` then, so `vivarc.css` gives a disabled `[data-name="Back"]` `pointer-events: none` while the option is on and the slot around it (`.button-toolbar`) gets `pointer-events: auto` and `app-region: no-drag` (the Dia top row with Vivaldi's frame off and the Arc sidebar's header are window-drag regions, which would take a real click as a drag), and a capture listener takes a click there only when it is real (`isTrusted`) and lands on that slot (a menu, the command bar or the Ctrl+Tab row over it keeps its click, `back.backClick`); the mouse's Back button reaches only the page (mousedown, mouseup, auxclick with button 3; the UI hears nothing), so while the option is on an opened tab gets a listener in its page (`webview.executeScript` at each commit, an isolated world) that sends `{ vivarcBack: "mouse" }` by `chrome.runtime.sendMessage` when the button is released on a page whose `navigation.canGoBack` is false; every window's UI hears it and the one holding the tab acts. Nothing is put into a page while the option is off. `back.last` says what the last Back did.
- The space-switch transition (`41-space-motion.js`, ported from upstream #85) follows `vm-active-space-changed`, which the sidebar sends when Vivaldi's record for this window names another space, so every way of switching gets it and a window's first look at its space does not. It animates only what is already on screen with the Web Animations API (opacity and transform: the page 180 ms at once, the Dia layout's page card as a whole; the list, `#vm-panel .vm-scroll`, 220 ms once the sidebar has drawn the new space, `vm-sidebar-rendered`, so the address field, favorites and space bar stay still), so nothing waits on it; a new switch cancels a running one, and `prefers-reduced-motion: reduce` skips it (`spaceMotion.last` says what the last switch did).
- A drop on the favorites grid itself (a gap between tiles; a drop on a tile is the tile's own) lands beside the nearest tile by its middle (`favDrop.slot`, `09-fav-drop.js`), before it or after it by the side of the middle the pointer is on; `wireDrop` hands `onDrop` the drop point as its third argument.
- Picking several tab rows (`09-select.js`, ported from upstream #147): `select.pick` decides each Ctrl/Cmd or Shift click (the tab on screen counts first, Shift runs from the last pick), the sidebar keeps the picked ids and paints `.vm-selected`, and `render()` drops ids no longer listed. Stack N Tabs is the drag-onto-a-tab folder move (`tabsPrivate.move` with `create-new-group`, 8.2's `target-is-tab` only on 8.2) for all of them, onto the top picked row, read back for the group and the space; Move N Tabs is `native.moveToSpace` with every id.
- The tab menu's `Move to New Window` and `Move to Window: <window>` are the tear-off and the drop without the drag: `toNewWindow(tabId)` (what `tearOffTab` runs once the drag is judged a tear-off, here with no position) and `intoWindow(tabId, windowId, indexOf, { focusAfter })` (what `dropAcross` runs, here for another window, last in its strip), each under the busy mark. The menu opens once `chrome.windows.getAll` is in (the browser's own menu is held back at once). Its Split View rows call the command bar's `splitView` (`window.__vm.splitView`, 20-command-bar.js).
- A tab row's `dragend` with `dropEffect === "none"` and a `screenX/screenY` outside `window.screenX/screenY/outerWidth/outerHeight` tears the tab off into a new window (`tearOffTab` in `10-sidebar.js`, decision in `workspaces.tearOff`). A drag with no known position reports `0,0`, which is treated as "stays". Escape cannot be told from a drop outside, so the tear-off offers Undo in a toast (`30-toast.js` takes `{ message, action: { label, run }, ms }`); `chrome.extension.getViews({ windowId })` reaches another window's UI to show it there.
- A mod has no API for Vivaldi's own commands. It has `chrome.*` and the `vivaldi.*` APIs Vivaldi's UI uses (`prefs`, `searchEngines`, `tabsPrivate`, `windowPrivate`, `runtimePrivate`, `contentBlocking`...), and it can reach Vivaldi's own code through its webpack modules: their chunk array is on the background page (`chrome.extension.getBackgroundPage().webpackChunkgapp_browser_react`), and a pushed entry is handed webpack's `require` (`requireOf`, below in Spaces). That is how Vivarc finds Vivaldi's workspace record, switch, move and delete, and its translation store, each by a marker in the module's source.
- Enum prefs set through `vivaldi.prefs.set` only take effect live when set by name (`"left"`, `"right"`, `"overlay"`). A number is stored but the UI ignores it until restart. The installer writes numbers because it edits the file while Vivaldi is closed.
- `auto_hide.enabled` is a master switch: when it is on, every bar defaults to hidden unless its own `auto_hide.*` key is explicitly `false`.
- A new profile's welcome tab is `chrome-extension://mpognobbkildjkofajifpdfhcoklimli/components/welcome/welcome.html`, and it can open after the mod has run. "Welcome to Vivaldi" is the start page's title, not the welcome tab's.
- Vivaldi does not write a pref that equals its default, so a key missing from `Preferences` does not mean the set failed.
- Profile switching uses Vivaldi's own UI API, which mods can call: `vivaldi.runtimePrivate.getUserProfiles(cb)` (entries have `name`, `path`, `active`, `guest`, `image`, `customAvatar`), `onProfilesUpdated`, `openNamedProfile(path, cb)` (takes the profile **path**, not the name) and `createProfile(name, imageIndex, createShortcut, cb)`. The chips live in Vivaldi's bottom toolbar (`.toolbar-tabbar-after`), a wrapping flex row that grows to fill the sidebar; its flexible spacers have a minimum width of about the whole sidebar, so the layout rule in `vivarc.css` turns wrapping off and removes that minimum for any toolbar that contains the chips (`:has(> .vm-spaces)`, no class on `#browser`, because Vivaldi rewrites that element's classes). Cmd+Ctrl+Left/Right (previous/next profile, wrapping, by name) and Cmd+Ctrl+1..9 are handled by `06-spaces.js`; `patch_preferences` and the runtime setup in `05-bootstrap.js` free those keys from any Vivaldi command. The account button is removed from `vivaldi.toolbars.tabbar_after` while there are two or more profiles, and the Downloads button is added to every profile.
- A tab belongs to a pin or favorite through two keys Vivarc adds to the tab's `vivExtData` (merged with Vivaldi's own keys, which share the field): `vivarcPin` is the bookmark id and `vivarcHome` is where the pin landed after the site's redirects, so a site that redirects off its root is not shown as away. Vivaldi saves them with the session, so the link survives a restart. Tabs that match a pin by URL when first seen are bound automatically; a key whose bookmark is gone is cleared. The logic is `src/js/08-pins.js`, covered by `tests/test_pins.py` (needs node).
- The Dia layout's Translate button is Vivaldi's own page translation, the calls its address-bar button makes: `vivaldi.tabsPrivate.translatePage(tabId, from, "en", cb)` and `revertTranslatePage(tabId, cb)`. What it shows comes from Vivaldi's translation store (`getPageState(tabId)`: `pageLanguage`, `isTranslated`, `translateStep`), found in the webpack modules as `findRemover` finds its manager (by `VIVALDI_TABS_LANGUAGE_DETERMINED`); `tabsPrivate.onLanguageDetermined`, `onPageTranslated`, `onIsPageTranslatedChanged` and `onShowTranslationUI` say when it changes. Measured on 8.2: Chromium determines a tab's language only once the tab is shown, so a tab loaded in the background has `pageLanguage: ""` and `chrome.tabs.detectLanguage` never resolves for it; a navigation clears the state; after a revert `translateStep` stays `after_translate`, so `isTranslated` is the one to read; translating a page that is already translated shows the original for a moment first; and once a tab has been translated, Chromium translates the next pages in that tab by itself.
- On a Mac with the sidebar hidden (`vm-sidebar-hidden`), the Dia top row would start at x = 0 under the traffic lights, so `vivarc.css` shifts it right by `--vm-dia-traffic`: 80px, or 86px on macOS 26 (`.macos26`), divided by `--uiZoomLevel`. That is Vivaldi's own room for the window buttons in `common.css` (`#browser.mac:not(.fullscreen) .window-buttongroup` margin-left 8px + min-width 54px, plus `.on-mainbar` margin-right 18px, 24px on macOS 26). Vivaldi exposes no variable for it, so a Vivaldi update may need the numbers re-read. A drag strip (`#main::before`) covers the room.
- A private window's UI (its own `window.html`) runs on the off-the-record profile: `chrome.extension.inIncognitoContext` is `true` there (`false` in a normal window), it has a background page of its own (Vivaldi's UI extension is split, not spanning, measured on 8.3), and its IndexedDB, BroadcastChannel and `chrome.windows.getAll` see only the private session. `vivaldi.prefs` is the real profile's. So `05-bootstrap.js` returns at once in a private window (its empty store looked like a new profile, and the setup reached every window: Task 8u), and `06-spaces.js` leaves the bottom bar's pref to the normal windows. A Guest window is probably off the record too and so skips the setup the same way (not measured).
- A private window cannot read the normal windows' Vivarc settings (their store and channel are on the other profile, and so is their background page), so its Dia layout follows the profile's prefs instead: `dia.inherits` is true while `vivaldi.address_bar.visible` is on, (on Windows) `vivaldi.windows.use_native_decoration` is off and `vivaldi.toolbars.navigation` has no `AddressField`, has the layout's `FlexibleSpacer` and no `PanelWidthSpacer`: the layout sets those (`dia.target`) and switching it off puts the address row back off, so they hold only while a normal window has it on. The row is checked that loosely so a Dia row edited in Vivaldi's toolbar editor still counts, and that far so an Arc-layout profile with Vivaldi's address row switched on by hand does not: its row is Vivaldi's default one or an edit of it, which (measured on 8.3) has an `AddressField`, a `PanelWidthSpacer` and a plain `Spacer`, and no `FlexibleSpacer` (the frame off is Vivaldi's own default on Windows, so it tells nothing apart). The price: a Dia row from which the user has removed the FlexibleSpacer opens private windows in the Arc layout. `01-settings.js` reads it when the window opens and again after `vivaldi.prefs.onChanged`, until the user flips Dia in that window; that switch stays in the window (no store write, no message). It writes nothing. Dia switched on in a private window while the normal windows have it off shows no top row: the address row is a profile pref the private window may not turn on.
- With Vivaldi's address row off (`address-top-off` on `#browser`: full screen, or the pref off), Vivaldi collapses the row to `max-height: 0`, hides its own buttons in it and moves its window buttons to the auto-hiding `#titlebar`. The Dia row is then `display: none` (vivarc.css), so Vivarc's buttons cannot centre on a 0 px row half above the window, and `fitRow` does not measure it until it shows again.
- The Dia layout's Shield (`.vm-dia-shield`, 15-dia.js) opens Vivaldi's own site-info popup by pressing Vivaldi's site-info button in the collapsed address field (`.UrlBar-AddressField .SiteInfoButton button.ToolbarButton-Button`) with `window.__vm.press` (00-core.js, marked as Vivarc's own, as 16-site-requests.js presses a permission icon). Measured on 8.3: the popup is `.SiteInfo.button-popup`, a child of that button (not an `.addressfield-popup-container`), `position: absolute` under it and clipped by the tab bar's `overflow: hidden`; it takes the focus; a second press of the button, Escape (the page then gets the focus) or a press anywhere else in the UI closes it, but a click on the page does not (the popup only loses the focus), so Vivarc closes it then with an Escape on the popup. While it is open `#browser` has `vm-shield-open`: the address field and its toolbar keep no height and are `visibility: hidden`, the popup alone is `visibility: visible`, `position: fixed` at `--vm-shield-x/-y` under the Shield (right-aligned to it, kept in the window, corrected for any containing block), Vivaldi's arrow is hidden, the glass sidebar's `backdrop-filter` is off (it would make the sidebar the popup's containing block and clip it), and with a Vivarc space colour the popup keeps Vivaldi's own `--colorFg`. Any other popup in the field (`.addressfield-popup-container` not carded, another `.button-popup`), the cursor moving anywhere else in the UI, or no popup within 800 ms drops the mark, and that popup drops from the toast anchor like the others (below); Ctrl+L, F6 or Alt+D while it is open close the popup, and the command bar takes the key (`12-sidebar-hide.js`). With the sidebar hidden (Ctrl+S) the tab bar is laid out again while the popup is open, with no width and nothing visible, so the popup can show. The watch runs on the whole UI (`document.body`), not the tab bar found at the press, so a tab bar Vivaldi puts up anew while the popup is open cannot leave the mark with no popup. A site question carded meanwhile (`16-site-requests.js`) is closed by the Shield's press (a press outside its popup) and would come back at once and close the Shield's popup in turn, so an open Shield popup (`vm-shield-open`, or Vivaldi's `.SiteInfo.button-popup`) counts as busy there: the question waits in its pill for as long as the popup is open and comes back once it closes. The blocker level it sets is Vivaldi's: `vivaldi.contentBlocking.getAllBlockingCategoryOverrides("ad_blocking", cb)` lists `{domain, selected_category: {blocking_category: "ad_blocking_N"}}` (the select's values: `off`, `ad_blocking_1` Light, `_2` Strong, `_3` Aggressive); Vivarc reads none of it (the Shield is always the same icon).
- The command bar replaces Vivaldi's address field for typing (Task 9b). The sidebar's field (`#tabs-tabbar-container .UrlBar-AddressField`) is always collapsed and `visibility: hidden`, which keeps Vivaldi's own `focus()` from reaching it at all (Ctrl+L with the cursor in the page, a new tab, a new window). Measured on 8.3: a new private window's first tab is `chrome-extension://mpognobbkildjkofajifpdfhcoklimli/components/private-intro/private-intro.html` (`workspaces.privateIntro`), Vivaldi focused the field within ~150 ms and it floated; the field is 348 px wide (its own minimum) in a 323 px sidebar, and taking the cursor while floated made Chromium scroll `#tabs-container` sideways (7 px at 323, 34 px at 272), moving the whole sidebar left (Byron's private-window bug). `#tabs-container` is now `overflow: clip` (a clipped box is not a scroll container, so nothing can scroll it), and 20-command-bar.js's focus guard, a fallback, takes the cursor out of the field (and any scroll back to 0) should it ever get it. The address keys open the bar in every normal window (`12-sidebar-hide.js`, `window.__vm.commandBar.ownsField()`), with the cursor in the UI by a capture `keydown` with `preventDefault()`, in the page by `onKeyboardShortcut`. The launch code opens the bar empty over a blank tab or the private intro page (`startsEmpty`). Task 8o's rule stays in the guard: a focus nobody asked for within 150 ms of a tab switch goes to the page.

## Spaces (Vivaldi workspaces)

- A workspace is `{id, name, emoji, icon, iconId}` in the pref `vivaldi.workspaces.list`. The store's changes run one after another across windows (a chain on the background page) and a write is raced against a timeout, like Clean Up's. `undelete` (the New Tab menu's Recently Deleted Spaces) re-creates the space with its id, its place (`orderAfter`), rules and theme, then its tabs (`restorePlan` over `backAlready`: a tab still carrying the id, or a default-space tab tagged `healedFrom` this id, matching a stored tab by address, is reused and its tag cleared once it is verified in the space; else a listed entry, by its id for the same address or after a restart by address and title; else a new tab put into the space with `setSpace`; pin, split and mute written back; every tab still carrying the id in another window is taken out of the space there first, matched or not, so the space is never split), checks their order (`inOrder`; on 8.3 one tab per `tabsPrivate.move`, each before the next, since a move of several does not reorder parked tabs), shows the space, then remakes its folders with Vivaldi's create-new-group move (8.3 drops a written `group`; Vivaldi clears a restored folder a moment after the restore and on the first switch, so each folder is checked after a second and remade, up to 3 times) and forgets the entry, unless a tab did not come back: each tab is read back in the space in the target window before it is counted (or its `healedFrom` cleared); one that is not stays in the entry (a retry brings it; a new tab of Vivarc's outside the space is closed again, a restored one is tagged `healedFrom` when in a default space), `undelete` returns `failed`, and the sidebar says so (`partialNote`). A window is closed as the restore's only when `sessions.restore`'s result names it (its `window`, or its tab's window) and it was not there before. Measured in the sandbox, task 9c (probes p1-p3).
- `18-empty-space.js` (Task 9c, Byron's D3): every window watches its own tab on screen; when it closes (a page) and the window holds no other page of that space, it makes or shows the space's blank tab under the busy mark (`decide`, pure) and opens the command bar on it through `window.__vm.openEmptySpace` (`20-command-bar.js`, the bar's keep-the-tab open), so Escape stays in the empty space. A newer gesture of the user's in that window during its 150 ms wait (a trusted pointerdown, a non-repeat keydown that is not a bare modifier, a Vivaldi shortcut pressed there; 60 ms of grace for the close's own key) or the record naming a third space after the wait makes it stand down; it checks again before the switch and before the bar.
- Moving a space to a new window: the window opens on `about:blank`, because a start page would open the command bar. Vivaldi's switch may not know a brand-new window yet, so it is retried until the tabs arrive. Then the `about:blank` tab closes.
- New tabs from Ctrl+T, + New Tab and the palette top their space's list, as in Arc (`workspaces.topIndex`). The list shows the highest tab index first.
  - Ctrl+T's blank tab moves there once it has an address.
  - The command bar creates its tab and then moves it, because Vivaldi's `tabs.create` ignores `index`.
  - Never moved: a tab in a folder (moving it would split the stack), a split view's new pane, the page whose address Cmd+L edits, and links a page opens.
- Cmd+Option+Left/Right are bound by `patch_preferences` and `05-bootstrap.js` to Vivaldi's `COMMAND_WORKSPACE_SWITCH_BACK_ORDER`/`_FORWARD_ORDER`, which skip workspaces open in another window and include the default space.
- Pinned folders: bookmark folders that contain a `Pinned` folder are spaces. A workspace takes the folder with its name (case-insensitive, an `Arc - ` prefix ignored); the default space is the first folder no workspace claims. A workspace with no folder gets an empty one when first shown. Favorites always come from the default space's folder. `plan()` in `08-pins.js` receives the pin ids of every space so a tab bound to a pin of another space is never cleared.
- Learned the hard way: Vivaldi normalises a shortcut to the order `ctrl+alt+shift+meta+key` and reads shortcut bindings at launch, so a binding the bootstrap writes live works from the next launch (an install that patches Preferences while Vivaldi is closed works at once). `window.vivaldiWindowId` is not Chrome's window id (`chrome.windows`, `tab.windowId`); every window runs its own copy of the mod, so per-window work (the repairs' leader check, for one) compares `tab.windowId` with `chrome.windows.getCurrent().id`.
- Deleting a space (right-click its tile, Delete Space…) calls Vivaldi's own `removeWorkspace`, which also closes the space's tabs. A mod has no API for it, and the webpack chunk array (`webpackChunkgapp_browser_react`) is not on the window the mod runs in: it is on the background page, `chrome.extension.getBackgroundPage()`. `findRemover` pushes a runtime callback onto that array to get webpack's module list, finds the module whose source mentions `removeWorkspace(` and takes the manager from its exports. If a Vivaldi update changes that, the sidebar shows a toast and deletes nothing. `removeWorkspace(windowId, id)` switches only the window it is given off the space, so the sidebar gives it the window that shows the space (when that window holds other tabs too), under the repair busy mark, and focuses the asking window again (task 9a). Learned by running a second Vivaldi with `--user-data-dir` and `--remote-debugging-port` and calling it from the Chrome DevTools Protocol.
