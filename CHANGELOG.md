# Changelog

## Unreleased
- A tab brought back from a **deleted space** with Vivaldi's own Reopen Closed Tab now shows up at once in its window's default space (it is marked as coming from that space), and **Recently Deleted Spaces** still brings it back into the space when you undelete it.
- A tab brought back from **Recently Closed** in the New Tab dropdown now comes to the window you picked it in, whatever space it was in: in its own space when that space can be shown there (the window then switches to it), else in the space on screen. Before, it went back to the window it was closed in.
- **Undelete a space.** A space you delete from its tile can come back from **Recently Deleted Spaces** in the New Tab menu, for 30 days (the last 10): the same space (Vivaldi's own, with its old id), its name, icon, place in the list, link-routing rules and theme, and its tabs in their old order, with their history while Recently Closed still lists them, in the window it lived in (or the one you ask from, if that window is gone). The delete confirmation says so; if Vivarc cannot keep the space for undo, it deletes nothing. Tabs Vivaldi brings back from a deleted space meanwhile go to their window's default space, and undelete takes them back. Spaces are edited, deleted and brought back from normal windows only (a private window says so).
- **Edit a space** from its tile's right-click menu: **Rename** (its Pinned folder is renamed first, so its pins stay with it), **Change Icon** (Vivaldi's own 20 icons, or an emoji), **Move Left** / **Move Right**; and the space bar's **+** now makes a space at once and opens its name for typing, instead of only reminding you of the shortcut. (Proposed upstream in KASOGIT/vivarc#126 by gulin-desigenr.)
- **Closing a space's last tab keeps you in that space**, empty, with the command bar open, as Arc does (and upstream, KASOGIT/vivarc#118/#119). Escape closes the bar and you stay in the empty space. Before, Vivarc took the window to its default space.
- Fix: **Copy Link** in a tab's or bookmark's right-click menu copies again while the page has the focus (after a click into it). It used to copy nothing, silently. (Ported from KASOGIT/vivarc#153.)
- Fix: with **Peek** on Vivaldi 8.3, **Open in New Tab** and **Open in Background** now put the page in the space on screen, right beside the tab the link was in. Before, it landed in the default space (Open in New Tab then snapped back out of view, and left a second copy behind). While a preview is open its tabs are no longer listed in the sidebar, Open Tabs, the command bar or Clean Up, and a preview no longer leaves two entries in Recently Closed. (Ported from KASOGIT/vivarc#166.)
- **Move to Space** now moves a tab into a space that is parked in another window (on Vivaldi 8.3): the tab joins that space there, that window keeps showing what it shows, and a toast says the tab went to another window. Before, Vivarc refused ("Show it there first"), though Vivaldi 8.3 can do it. On 8.2 the refusal stays, now naming the space.
- Fix: deleting a space that is shown in **another window** switches that window to its default space first, so it is never left showing the deleted space (new tabs opened there in that moment used to vanish into it). The window you deleted it from keeps the focus.
- Fix: tabs left in a **space that no longer exists** (restored from Recently Closed, with Vivaldi's own Reopen Closed Tab, or kept in the session across a restart) now move to their window's default space by themselves, where you can see them again. This also heals a profile that already has such tabs, on its next start. It only happens once Vivaldi's space list has loaded and reads the same twice, so a list still loading at start-up moves nothing. A window is also no longer switched into a deleted space when its last default tab closes.
- Fix: a tab of a **deleted space** brought back from Recently Closed (or picked in the command bar, Open Tabs or Recently Cleaned) now opens in the space on screen in the window you clicked in. Before, Vivarc switched the window into the deleted space for a moment (the tabs flashed up, then the window fell back to its default space) and left the tab where no tile could show it; Vivaldi 8.3 brings such a tab back with the deleted space's id. The command bar no longer puts such a tab's Switch to Tab first or autocompletes its address, which used to throw you out of the space you were in and lose the new tab.
- Fix: space folders in Vivaldi's bookmark Trash no longer count as spaces (thanks to KASOGIT/vivarc#117).
- Fix: web addresses offered as command-bar suggestions open directly instead of running a search (thanks to KASOGIT/vivarc#108).
- Fix: links inside Favorites subfolders no longer hide matching tabs from the sidebar (thanks to KASOGIT/vivarc#87).
- **Open Tabs** in the New Tab dropdown now labels every group with its window, space and tab count, under muted headings that preserve names' case, with stronger dividers between windows; this window stays first.
- **Recently Closed** now shows up to 20 (was 10) tab entries from the latest 25 sessions; closed windows remain in their separate list and are not expanded into tabs.
- The **New Tab** dropdown chevron is always visible in Dia and Arc, with brighter hover, focus and open states in the current theme's colours.
- Fix: first setup applies Revival Arc's layout; later installs, updates and reruns of Vivarc's own in-browser setup keep your Auto-Hide choices, panel position and status-bar display, including settings reset to Vivaldi's defaults (thanks to KASOGIT/vivarc#132).
- Fix: on Windows, installing or updating from a release (`install.bat`) no longer fails when Git for Windows' `tar` comes before Windows' own on PATH: it always uses Windows' `tar`, which reads the `C:` paths Git's rejects.
- **Wallpaper behind the sidebar**: an option in Vivarc Settings, off by default. It shows your Vivaldi theme's background image behind the sidebar, lined up with the window, under a tint of the theme's own colour so the text stays legible. With Liquid Glass the glass opacity sets how much tint there is (never too little to read). A space with its own colour from the theme editor keeps its colour, and Reduce Transparency or Increase Contrast turn the image off. From KASOGIT/vivarc issue #62.
- **Back closes opened tabs**, like Arc: an option in Vivarc Settings, off by default. When it is on, Back on a tab that a link in another tab opened, with no page of its own to go back to, closes the tab and shows the page the link was on. It works from Alt+Left (Cmd+Left on a Mac, or whatever Back key Vivaldi has), the mouse's Back button and the Back button. A tab that has gone on to other pages goes back as usual; pinned tabs, favorites, split views, a tab whose page is in another window or space, and a Cmd+Left typed in a text field are left alone. Vivarc remembers which tab a link opened until Vivaldi restarts. From KASOGIT/vivarc#168 (open upstream), without its swipe detection.
- Switching spaces has a short transition: the sidebar's list fades and rises into place and the page fades in, in a fifth of a second. The switch itself is not delayed, and Reduce Motion turns the transition off. Ported from KASOGIT/vivarc#85.
- Fix: a favorite (or a tab) dropped in a gap between favorite tiles lands beside the nearest tile, on the side you dropped it, instead of at the end of the grid. While you drag, the tiles no longer grow under the pointer with Liquid Glass on, and the drop marker shows over the glass tiles. Ported from KASOGIT/vivarc#138.
- **Pick several tabs**: Ctrl+click tab rows (Cmd+click on a Mac) to pick them, Shift+click to pick a range; the tab you are on counts as picked. Right-click a picked tab for **Stack N Tabs** (one tab folder, named as it is made), **Remove from Folder**, **Move N Tabs to <space>**, **Close N Tabs** and **Clear Selection**. Escape or a plain click lets go. Ported from KASOGIT/vivarc#147.
- A tab's right-click menu has **Reload Tab**, **Split View: Side by Side** and **Top and Bottom** (the command bar's split view, with this tab), **Close Split View** on a tab in one, **Move to New Window** and **Move to Window: <its tab>** for each of your other windows. Move to New Window works as dragging the tab out of the window: it opens in a new window's default space, with Undo. Move to Window works as dragging it into that window's sidebar: it joins the space that window shows and that window comes forward. Ported from KASOGIT/vivarc#134 and #136, on Vivarc's own moves so the space rules hold.
- **Ctrl+Tab switcher, like Arc's** (Ctrl on a Mac too). Hold Ctrl and press Tab for a row of your recent tabs with thumbnails, the tab you are on first; Tab or Shift+Tab (or the arrow keys) move through it, and holding Tab moves faster and faster. Let go of Ctrl to switch, Escape to stay. A quick Ctrl+Tab goes straight to the previous tab. It lists only this window's tabs in the space on screen, so it never switches you to another space or window. Vivarc takes Ctrl+Tab and Ctrl+Shift+Tab from Vivaldi's own tab cycling once per profile; Vivaldi reads its keys at launch, so restart it once, and until then Ctrl+Tab stays Vivaldi's. Ported from KASOGIT/vivarc#93.
- **The command bar replaces Vivaldi's address field.** Ctrl+L (Cmd+L), F6 and Alt+D open the command bar with the page's address to edit, with the sidebar shown or hidden (before, with the sidebar hidden, Ctrl+S or Cmd+S on a Mac, they did nothing: the address field lives in the hidden sidebar; now the sidebar stays hidden). Whatever else would put the cursor in Vivaldi's own field (a new tab, a tab switch, a new window) opens the command bar instead, so the field no longer floats over the sidebar. The one exception is a single entry the command bar hands to Vivaldi's field on purpose: **Open in Vivaldi's address field** and the addresses and searches the bar leaves to Vivaldi (below) show the field for that entry, and it hides again once it loses the cursor. A **new private window opens the command bar**, empty, over its introduction page; Esc closes it. Fix: a new private window no longer comes up with Vivaldi's address field focused and floating and the sidebar shifted left. The field, wider than the sidebar, made Chromium scroll the sidebar sideways when it took the cursor; the sidebar can no longer be scrolled that way at all. Fix: clicking a tab no longer pops Vivaldi's hidden address field open over the sidebar. A tab left with the cursor in the address field (Ctrl+L, then a switch) used to put it back there on every return; when that happens just after a tab switch and you did not ask for the field (no Ctrl+L, Cmd+L or F6, no click on it, no typed text, no permission popup), the page gets the cursor instead.
- **Notifications** drop down just under the page's site and title (Dia layout) or the URL bar at the top of the sidebar (Arc layout), instead of the top right: a site's question (with readable words for Vivaldi's raw "window-placement" and "local-fonts"), Vivarc's own messages (the Undo after dragging a tab out), and new short notes for a **blocked pop-up** (Allow is Vivaldi's own Always Allow for the site, and opens the page), a **zoom change** (Reset) and **Ctrl+D** (Bookmarked, Edit). Three show as rows; a fourth folds them into one stack that opens on a click. A question never times out; its close keeps it pending (a pill brings it back), except Vivaldi's "open all ... links" question, where closing is Vivaldi's Deny and the card says so. Each tab keeps its own: they hide on a switch and come back on return.
- With the command bar open, a **fly-up right above it** shows everything about the page (when the bar edits its address): a site's question (answer it there, with Vivaldi's own buttons), any other note, permissions you gave or blocked, a blocked pop-up, an insecure connection, the zoom, and the page's own actions (site info, translate, reader view, feeds, install app, QR code), which open Vivaldi's own panels. Vivarc never opens the bar by itself to show something.
- Vivaldi's own panels of its hidden address field (a site's USB, Bluetooth, HID or serial device list, an answered permission's panel, blocked pop-ups, translate, the bookmark editor, install app) now drop from the same place as the notifications, and the address field no longer comes with them. Before, most of them opened invisibly (Vivaldi hides those buttons in a side tab bar) and the rest floated the field over the sidebar.
- The command bar reads what you type the way Vivaldi's address field does: `localhost:3000`, an IP address with a port (IPv4 or IPv6), an intranet name with a path or a port, a file path (`C:\Users\...`), `file:`, `about:`, `view-source:`, `chrome:`, `vivaldi:`, `data:` and other schemes load as addresses; a bare word is a search with its intranet address offered as a second row; text that looks like an address but is not a valid one (`[1]`, `999.1.1.1`, a port over 65535 or a port that is not a number, a space in a host) is shown in Vivaldi's own field for you to correct, never searched. Address-shaped text is not sent to the search engine's suggestions while you type. A search engine that searches by POST goes through Vivaldi's own field named by its own keyword (the default engine's too), so it stays that engine's search (never DuckDuckGo, never read as an address); an engine with no keyword, or the default when Vivaldi's engines cannot be read, shows the words there for you to press Enter. An address Vivaldi will not load from the bar goes through its own field. **Open in Vivaldi's address field**, the last row whenever you type, shows Vivaldi's own field for that one entry (an extension's keyword, Vivaldi's own suggestions) and hides it again; a `javascript:` (or `vbscript:`) address, and a `data:` address, go there too and are never submitted for you, however they are written: you press Enter. A tab-switching shortcut (Ctrl+Tab, Ctrl+PgDn, Ctrl+1...) never opens the command bar, even when the tab you switch to had the cursor in its address field. Vivaldi's own "focus the address field" commands (its menu, your custom shortcuts, a new tab or window) open the command bar. Tab moves from the bar's input into its fly-up and back; Escape there returns to the input.
- The command bar grows with windows larger than 1920 x 1080, up to 1.2x (ported from KASOGIT/vivarc#142); the row you pick with the arrow keys fills the field (#129); **Move Tab to Space…** in the command bar picks a space and takes you there with the tab (#143); one click outside the bar on a sidebar row closes the bar and opens that row, instead of two clicks (#119).
- Fix: **Move to Space**, dragging a tab out into a new window (and its Undo), dragging a tab into another window's sidebar, clicking a favorite or pin whose tab is in another space or window (it is brought here), and Clean Up's restore of a cleaned tab into its space now work on Vivaldi 8.3. Vivaldi 8.3 ignores a space written to a tab's data, which is how Vivarc used to set it; Vivarc now moves the tab with Vivaldi's own move (the one its Move to Workspace uses) and checks that it landed. On 8.2 Vivarc still writes the space, and now says so if it does not land.
- Fix: with the sidebar hidden, a question Vivaldi asks in its address field that Vivarc does not show as a card (a site's USB, Bluetooth, HID or serial device list, an answered permission's panel, any other question of that kind) now shows, the sidebar staying hidden and the page not moving. Before, it was invisible. It goes when you answer it.
- Fix: in the Dia layout, the **Shield** now stays open when a site has a question pending. Before, the question's card came straight back and closed the Shield's panel; now the question waits in its "Site request pending" pill while the panel is open and comes back as a card once it closes.
- Fix: a drag that only claims to be a sidebar tab (made by a web page or another app) can no longer move a tab between windows: a sidebar takes a tab from another window only with a one-time pass that a real drag from another sidebar leaves.
- Fix: Clear and Close All Tabs say so when the tabs could not be closed, and close nothing if the new tab that keeps the window open could not be made. A Vivarc module that fails while handling a key or a settings change no longer stops the others from getting it.
- Fix: a click on the sidebar (the New Tab chevron, a tile, a row) is no longer lost when the sidebar refreshes or Vivaldi re-renders the tab bar while the mouse button is down. The refresh, and putting the sidebar back in place, now wait for the release.
- Dia layout: a **Shield** button in the top row opens Vivaldi's own site-info panel under it (connection, cookies, site settings, JavaScript, the Ad and Tracker Blocker's Off / Light / Strong / Aggressive, Privacy Report), with the address field staying collapsed. Escape, a click elsewhere or a second click on the Shield closes it, and the page keeps the cursor. Anything else Vivaldi opens there still floats the address field as before.
- Dia layout: Copy link and Translate are now icon buttons (a share icon, and 文/A for Translate) with tooltips, the size of the row's other buttons, in the order Shield, Copy link, Translate. Translate still shows only on pages not in English; translated, it looks pressed and its tooltip says Show original, and it pulses while translating. In a narrow window the title goes first, then Translate, Copy link and the Shield.
- A private window opens in the Dia layout when your normal windows use it, and in the Arc layout when they do not. Switching Dia on or off in a private window changes that window only and is not saved.
- Fix: opening a private window no longer changes your profile. The first private window of a session used to run Vivarc's new-profile setup against your real profile: it turned Vivaldi's address bar off in every window (which pushed the Dia layout's top row half off the window and brought Vivaldi's own title bar back), reset the sidebar width to 323, and put back the auto-hide, panel, status-bar and extension-menu choices. A private window now sets nothing up. If your address bar or sidebar width changed after opening a private window, set it once more (or switch Dia off and on in a normal window).
- Fix: in full screen the Dia layout's top row goes away with Vivaldi's own buttons, instead of the sidebar button and the page's title showing half above the page at the top-left.
- A site's permission question (notifications, location, camera, microphone...) now shows as a **card at the top right of the page** with the site, what it asks for and a button for each of Vivaldi's own (Allow, Deny, in Vivaldi's labels), instead of Vivaldi's address field floating open over the sidebar. A click answers exactly as clicking Vivaldi's prompt would, **×** or Escape closes it (the request stays pending, as when you close Vivaldi's prompt, and a small "Site request pending" pill keeps it one click away), no key ever answers it, a double-click never answers the card that moves up under it, and the page keeps the cursor. A click elsewhere in the window, or switching away and back, brings the card back. A popup Vivarc cannot read (the permission panel of an answered request, a device list, a protocol-handler question, anything new) still floats the field, so a question is never hidden.
- A way back to Vivaldi's Start Page (Speed Dials): a **Start Page** row in the New Tab dropdown opens it in a new tab here, and typing its address (`chrome://vivaldi-webui/startpage`, `vivaldi://newtab`) in the command bar or Vivaldi's address field goes there and stays, with the sidebar listing the tab. Ctrl+T and + New Tab still open the command bar. A start page Vivaldi opens by itself still counts as a blank tab, and navigating the tab away makes it an ordinary page again.
- Fix: Vivaldi's right-hand panel (auto-hidden) slides in when the pointer pauses in the gap at the window's right edge (6 px, 8 px in the Dia layout), which fixes it on a monitor whose right edge meets another screen. Vivaldi only reacts to the pointer in the window's last 4 px, and only while the pointer is over the window, so there the pointer usually passed that strip without stopping. Vivarc watches the gap in the window's own coordinates and asks Vivaldi to show the panel, with Vivaldi's own checks; a pointer flung straight onto the next monitor does not pop it. In the Arc layout a maximised window keeps a 6 px gap at the right (as an unmaximised one already has), so the page's scrollbar is never under the edge. A monitor with a real right edge where the panel also failed (a 4K above the others) is still to be checked.
- **Mute a tab**: right-click a tab row for **Mute Tab** / **Unmute Tab**. A tab playing sound shows a small speaker before its name: click it to mute. A muted tab shows a crossed-out speaker in place of its favicon: click it to unmute. Pinned rows work the same, and a muted favorite's tile carries a small crossed-out speaker over its corner. Mute All Tabs shows on the rows too.
- **Clean Up Tabs** in the New Tab dropdown closes the tabs of the space on screen that you have not used for 7 days, then offers **Undo** in a toast. **Clean Up Daily** (a ✓ toggle in the same menu, and in Vivarc Settings; off by default) does it once a day for every space in every window, quietly. Pinned tabs, favorites, the tab on screen in any window (and the tabs beside it in a split view), tabs playing sound and private-window tabs are never cleaned; tabs in folders are. A tab only closes once its entry is confirmed in Recently Cleaned, so a run bigger than the list's 200 leaves the rest open. Cleaned tabs wait in **Recently Cleaned** for 30 days (up to 200): click one to reopen it in its space, or Clear list.
- The New Tab dropdown's confirmations (Close All Tabs, Clear list) open with Cancel under the pointer, so a double-click cannot confirm. The chevron's highlight goes out whenever the menu closes, Mute All Tabs carries on past a tab that cannot be muted and says how many failed, and picking a tab in a minimised window brings that window back.
- A dropdown on the **+ New Tab** row: hover it and a chevron shows at the right; the rest of the row still opens the command bar. The menu has Search Tabs, an Open Tabs list (every window, by space), Recently Closed tabs, Recently Closed Windows, Mute/Unmute All Tabs and Close All Tabs (asks first; the same tabs the Clear button closes). Lists open as side flyouts.
- Fix: on a Mac, with the Dia layout and the sidebar hidden, the top row starts after the traffic lights instead of running under them, with the room Vivaldi itself leaves for them. The strip beside them still drags the window.
- Dia layout: a **Translate** button left of Copy link, on pages that are not in English. It translates the page into English in place with Vivaldi's own translation, which the Dia layout otherwise hides with the address bar. Once the page is translated, the button says **Show original**.
- Ctrl+shift+click a space tile (cmd+shift+click on a Mac) to move the space to a new window of its own, the reverse of shift+click's "bring it here".
- Drag a tab from one window's sidebar into another window's sidebar: it moves there, at the drop position, into the space that window shows, and becomes the active tab. The window you dragged from keeps showing its space. The middle of a row counts as its nearer edge: no folder is made across windows.
- Drag a tab out of the sidebar, past the window's edge, to open it in a new window. The tab goes into that window's default space and leaves its space; the window you dragged from keeps showing its space. Pins, favorites and folders stay, and so does a window's only tab. A drop onto another window's page also opens the new window. Escape does not cancel a drag that has left the window, so a toast offers **Undo** for 5 seconds (it puts the tab back, in its space; a split view or folder is not restored). A tab in a split view leaves it, and so do its partners.
- A git clone of Revival Arc is no longer offered upstream's releases by the update reminder: it updates with `git pull` from its own fork. The "Vivaldi was updated" reminder stays.
- A space that lives in another window has a dot on its tile, whether it is shown there or parked there. Before, only a space shown in another window had one. The default space's tooltip says it holds this window's own tabs.
- Clicking a space tile goes to where the space lives. A space shown in another window brings that window to the front. A space parked in another window is shown there, and that window comes to the front. Before, its tabs were pulled into this window. A plain click no longer moves tabs between windows, except to gather a space split across windows into the window it lives in. Shift+click still brings a space here.
- New tabs, links included, open in the space on screen, which is how Vivaldi files them. Vivarc no longer stamps new tabs itself. Its stamping could undo a switch to the default space and file the next tab in the old one.
- New tabs from Ctrl+T, + New Tab and the command bar open at the top of the space's list, as in Arc. Links opened from a page still open next to it.
- Fix: clicking a favorite or a pinned tab whose tab is in another space or window brings that tab here, into the space on screen. Before, a second tab opened.
- Vivarc puts things right when Vivaldi lets them drift:
  - A window left on a deleted space, or on a space it has no tab of, goes to its default space.
  - A window that shows a tab of one space while Vivaldi records it on another is put back in step.
  - A space split across windows, for example after a window closes, is gathered into one window.
- A tab dragged into another window with Vivaldi's own drag (between tab strips) joins the space that window shows. That is Vivaldi's own behaviour. A tab dragged between sidebars is Vivarc's own drop (above) and lands the same way. Tabs rehomed from a closing window keep their space.
- Picking a tab of another space in the command bar shows that space, with the tab on screen. Before, the window could jump straight back to the space it was on.
- Deleting a space: the confirmation counts the space's tabs in every window, and says when a window holding only those tabs will close too.
- Right-click a tab in the sidebar and pick **Move to <Space>** to move it to another space, with Vivaldi's own move. The window stays on the space it shows. If the space is shown in another window, the tab goes to that window. A space parked in another window is refused with a message on Vivaldi 8.2: show it in its window first (on 8.3 the tab now goes there, see **Move to Space** above).
- The sidebar hides in one window at a time. Ctrl+S (Cmd+S on a Mac) hides and shows the sidebar of the window you press it in, in both layouts, and the Dia layout's new button in the top row, between Vivaldi's menu button and Back, does the same. Other windows keep theirs. Before, the hide was Vivaldi's own, one setting for every window at once.
- Ctrl+S is now Vivarc's. On a profile's first start after this, Vivarc takes the key off whatever Vivaldi command holds it (the tab bar's hide, its auto-hide, Save Page) and says so in the console, once. Vivaldi reads its keys at startup, so quit and reopen it once after that start. A hidden sidebar no longer slides back in when you move the pointer to the left edge of the window; press Ctrl+S (or the Dia button) to bring it back.
- Peek opens on shift+click on a link (or a middle-button hold) and never on a plain click. Before, alt+click opened it, and so did a plain click in pinned tabs and on Google pages. Shift+click on a link opens Peek instead of a new window. `"peek": false` in `~/.vivarc/config.json` keeps Peek out, including after "Update Vivarc", and the Windows re-apply task now puts Peek back unless it is turned off.
- Pinned folders slide open and shut instead of appearing at once. With Reduce Motion on, they still open instantly.

## 0.1.16 - 2026-10-28
- **Uninstall Vivarc**: the installer now also leaves `~/Applications/Uninstall Vivarc.app` next to Update Vivarc. It quits Vivaldi, restores your settings, removes Vivarc and reopens Vivaldi, so removing or reinstalling no longer needs Terminal.
- Docs: the README and the guide page now say that a sidebar hidden with Cmd+S slides back in when you move the pointer to the left edge of the window.

## 0.1.15 - 2026-10-27
- Right-click a space tile and pick **Delete Space…** to remove it; a second step asks first and says how many tabs will close. The space's Pinned folder stays in your bookmarks and comes back if you create a space with the same name. The default space cannot be deleted.

## 0.1.14 - 2026-10-27
- The update reminder also tells you when a new Vivarc release is out: one dialog per release, and on yes it runs Update Vivarc. It needs the reminder to be on (`reminder on`).

## 0.1.13 - 2026-10-27
- Fix: sites could not ask for the camera or microphone (Google Meet's "Allow" did nothing). Vivaldi shows these requests under the address bar, which Vivarc keeps collapsed, so they were invisible. The address bar now floats over the sidebar, as with Cmd+L, while such a popup is open, and is no longer cut off by the page when a theme is on.
- **Liquid glass** (off by default; turn it on in Vivarc Settings): a translucent, blurred sidebar, menus, command bar and dialogs, following Apple's Liquid Glass guidance (glass only for navigation and controls, never stacked, legible text) and falling back to solid surfaces when macOS has Reduce Transparency or Increase Contrast on. A **Glass opacity** slider in the settings goes from clear to frosted.
- **Vivarc Settings**: Cmd+T, type `settings`, or right-click the sidebar and pick Vivarc Settings… to switch features on and off live: the space bar, the compact bottom bar and search suggestions. Saved per profile and applied in all of the profile's windows; `~/.vivarc/config.json` still sets the starting values.
- Cmd+T quick actions **Collapse All Folders** and **Expand All Folders** fold or unfold every pinned folder in the sidebar at once (type `collapse`, `expand` or `folders`).

## 0.1.12 - 2026-10-26
- Spaces: Vivaldi workspaces become Arc-style spaces. A row of emoji tiles under the sidebar switches between them; each space lists only its own tabs (Clear and Close Other Tabs stay inside it) and has its own Pinned folder, named after the workspace (an imported `Arc - Work` folder goes with a workspace called Work, and a new workspace gets an empty one). Favorites are shared by every space, and a tab you open (command bar, link, sidebar) stays in the active space. A space only groups tabs: logins are shared, profiles remain the way to separate them.
- Cmd+Option+Left/Right now switches to the previous/next space (Vivaldi's own workspace commands). The profile switcher's previous/next moves to Cmd+Ctrl+Left/Right; Cmd+Ctrl+1..9 is unchanged.
- **Ctrl+Cmd+N** opens Vivaldi's Create Workspace dialog (name, icon or emoji). The **+** tile under the sidebar and **Create New Space** in the Cmd+T bar remind you of it: a mod cannot press a shortcut for you.

## 0.1.11 - 2026-10-24
- Right-click a favorite or a pinned tab and pick Rename… to change its name. A favorite's name is edited in a field under its row (the tile only shows the icon); Enter saves, Escape cancels.
- Fix: some favorites (Gmail for example) showed a letter instead of their icon after restarting Vivaldi, until they were opened again. Large favicons are now shrunk to 64px before being cached, instead of not being cached at all.
- Profile switcher: the bottom bar shows your Vivaldi profiles as round avatars in place of the account button. Click one to open or focus that profile, or press Cmd+Ctrl+1..9. A **+** creates a new profile and right-clicking your own avatar opens Vivaldi's profile manager.
- Cmd+Option+Left/Right switches to the previous/next profile, like Arc's spaces (it replaces Vivaldi's own use of that combo for switching tabs; Ctrl+Tab still cycles tabs).
- Every profile now gets the Downloads button in the bottom bar (profiles without Vivaldi's VPN button never had it).

## 0.1.9 - 2026-10-24

## 0.1.8 - 2026-10-24

- The sidebar can no longer be resized below 220px.

## 0.1.7 - 2026-10-23
- Like Arc, a pinned tab stays on its pin when you navigate inside it, instead of turning into a separate open tab and leaving the pin looking closed. The row shows a `/` and the current page's title (the pin's name is in the tooltip); hover it for "Back to pinned page" and "Separate From Pinned Tab" (also in the right-click menu, and for favorites). The link is stored in the tab's session data, so it survives a restart.
- Behaviour change: only the tab bound to a pin is hidden from the open tabs list. A second tab on the same site now shows up as a regular tab.

## 0.1.6 - 2026-10-23
- Update Vivarc is now a real app (`~/Applications/Update Vivarc.app`) that you can drag to the Dock; it opens the update script in Terminal. The plain script moved to `~/.vivarc/` and the old one in `~/Applications` is removed on the next install.

## 0.1.5 - 2026-10-23
- Fix: the installer's questions ("Quit Vivaldi now?", the App Management "press Enter" step) never reached the terminal and always fell through to "nothing was changed". They now work.
- `update` (and so Update Vivarc and the reminder) closes Vivaldi by itself, and the Update Vivarc script reopens it afterwards, also when the update fails.

## 0.1.4 - 2026-10-23
- Optional update reminder: `install` asks once; when a Vivaldi update has removed Vivarc, a dialog offers to bring it back (opens Update Vivarc). Turn it on or off with `reminder on|off`; `uninstall` removes it.

## 0.1.3 - 2026-10-23
- `update` command: fetches the latest release (or pulls a git checkout) and re-applies it. The installer leaves a double-clickable "Update Vivarc" in your Applications folder that runs it after a Vivaldi update and reopens Vivaldi. `uninstall` removes it. If you are on 0.1.2, paste the install line once to get it.

## 0.1.2 - 2026-10-23
- One-line installer for everyone (also updates and repairs): downloads the latest release and runs it, no git needed.
- The installer checks that macOS allows editing Vivaldi before changing anything, opens the App Management settings page and waits, offers to quit Vivaldi, refuses to run as root, and detects files left owned by root after an earlier sudo run.
- `apply` works while Vivaldi is open; the bundle is written atomically.

## 0.1.1 - 2026-10-23
- Fix: the sidebar could stay empty after a restart when tab events cancelled the first bookmark load.
- Added a contributing guide, issue templates and a demo GIF in the README.
- Quick actions Split View: Side by Side, Split View: Top and Bottom and Close Split View, built on Vivaldi's tab tiling. A split tab shows a ◫ mark in the sidebar.

## 0.1.0 - 2026-10-23
- Sidebar: favorites grid, pinned folders, divider with Clear, open tabs in one scrollable panel.
- Drag and drop between favorites, pinned folders and open tabs; context menus; inline folder rename.
- Command bar on Cmd+T: tabs, bookmarks, history, URLs, search suggestions, `yt` + Tab engine mode.
- Cmd+Shift+C "Copied Current URL" toast.
- Theme editor: sidebar colour, shade and grain, saved per profile.
- Layout applied to every profile: address bar and back/forward/reload inside the sidebar toolbar, profile and Downloads buttons at the bottom, panel bar on the right with auto-hide, status bar in overlay mode, sidebar width 323.
- First run of a profile: starter favorites (Gmail, Calendar, Drive, YouTube, GitHub, Maps) and example pins (a link, a folder, a nested folder); the guide page replaces Vivaldi's welcome tab.
- Quick actions in the command bar, 18 built-in search shortcuts, Cmd+S sidebar toggle, Downloads button, guide page.
- Profiles created after install are set up automatically, live (no restart). The stylesheet is embedded in the injected script: no CSS-mods folder or Vivaldi flags.
- Installer with backups, per-profile snapshots, uninstall; Arc importer (spaces to bookmarks, site icons).
- Optional Peek link preview, downloaded from upstream at a pinned commit.
